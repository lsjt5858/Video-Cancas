# 02 - 系统架构

## 1. 总体架构

系统采用前后端分离 + 异步任务队列 + 对象存储的架构。

```text
Browser
  -> Web App
  -> API Server
  -> PostgreSQL
  -> Redis Queue
  -> Worker
  -> AI Model Gateway
  -> Object Storage
  -> FFmpeg Exporter
```

核心原则：

```text
交互在前端
业务规则在 API
长任务在 Worker
大文件在对象存储
模型调用走统一网关
画布状态可持久化、可恢复
```

## 4. 服务职责

| 服务 | 职责 |
| --- | --- |
| Web App | 画布交互、分镜编辑、素材预览、任务进度展示 |
| API Server | 项目、分镜、节点、素材、任务、导出的业务接口 |
| Worker | LLM、生图、生视频、转码、导出等耗时任务 |
| AI Model Gateway | 屏蔽不同模型供应商差异，统一输入输出 |
| Object Storage | 存储图片、视频、音频、缩略图、导出包 |
| PostgreSQL | 存储结构化业务数据 |
| Redis | 任务队列、任务进度缓存、短期状态 |

## 5. 数据流

### 5.1 剧本拆分

```text
用户提交剧本
  -> API 保存 script
  -> API 创建 ai_task
  -> Worker 调用 LLM
  -> Worker 写入 scenes / shots
  -> API 推送任务完成事件
  -> 前端刷新分镜表和画布节点
```

### 5.2 图片生成

```text
用户点击分镜生图
  -> API 创建 image_generation task
  -> Worker 组装 prompt 和参考图
  -> AI Model Gateway 调用图片模型
  -> 保存图片到对象存储
  -> 写入 assets
  -> 关联 shot 和 canvas node
  -> WebSocket 通知前端
```

### 5.3 视频生成

```text
用户选择图片生成视频
  -> API 创建 video_generation task
  -> Worker 获取首帧图片和 video_prompt
  -> AI Model Gateway 调用视频模型
  -> 保存视频到对象存储
  -> 写入 assets
  -> 更新 shot.selected_video_asset_id
  -> 前端节点显示视频结果
```

### 5.4 导出

```text
用户点击导出
  -> API 创建 export task
  -> Worker 读取 timeline
  -> Worker 下载/定位素材
  -> FFmpeg 合成 MP4
  -> 打包素材、分镜表、timeline.json
  -> 写入 export record
  -> 前端展示下载地址
```

## 6. AI Model Gateway

模型接入层必须使用适配器模式，避免业务代码直接依赖某个供应商。

```text
ModelGateway
  ├── LLMProvider
  ├── ImageProvider
  ├── VideoProvider
  ├── TTSProvider
  └── ReviewProvider
```

统一请求结构：

```json
{
  "provider": "provider_name",
  "model": "model_name",
  "task_type": "text_to_image",
  "input": {},
  "config": {},
  "metadata": {
    "project_id": "uuid",
    "shot_id": "uuid"
  }
}
```

统一响应结构：

```json
{
  "status": "success",
  "assets": [],
  "raw_response": {},
  "usage": {},
  "error": null
}
```

## 8. 关键设计约束

```text
节点 data 可以扩展，但必须有 node_type 和 project_id
AI 任务必须异步执行，API 不等待生成完成
素材只能存储 URL/对象 key，不把大文件放数据库
所有生成结果必须关联 ai_task，方便追溯和重试
时间线第一版只做线性粗剪，不做多轨复杂编辑
剪映草稿导出必须做成 adapter，不能侵入主业务模型
```
