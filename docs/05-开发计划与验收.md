# 05 - 开发计划与验收

## 1. 开发原则

```text
先打通闭环，再扩展深度
先做可编辑结果，再做自动化增强
先保证数据可追溯，再优化体验
先做素材包和 MP4，再做剪映草稿
```

## 2. 阶段计划

### 阶段 0：工程初始化，2-3 天

目标：能本地启动 Web、API、数据库、Redis、对象存储。

任务：

```text
初始化 monorepo
创建 apps/web
创建 apps/api
创建 apps/worker
创建 infra/docker-compose.yml
配置 PostgreSQL、Redis、MinIO
建立 .env.example
创建基础 README
```

验收：

```text
Web 能打开首页
API 健康检查通过
数据库迁移能执行
Worker 能连接 Redis
MinIO 能创建 bucket
```

### 阶段 1：项目、剧本、分镜，1-2 周

目标：完成最基础的数据管理。

任务：

```text
projects CRUD
script 保存和读取
shots CRUD
分镜表 UI
项目详情页面
基础 API client
```

验收：

```text
可以创建项目
可以粘贴并保存剧本
可以手动新增/编辑/删除分镜
刷新页面后数据保持
```

### 阶段 2：无限画布，1-2 周

目标：分镜可以同步成画布节点，并支持基础交互。

任务：

```text
React Flow 接入
canvas_nodes CRUD
canvas_edges CRUD
分镜转节点
节点拖拽保存
节点属性面板
画布视图和分镜表联动
```

验收：

```text
分镜能生成 shot 节点
节点位置拖动后能保存
节点属性修改后分镜同步更新
节点之间可以连线并持久化
```

### 阶段 3：LLM 拆分和提示词，1-2 周

目标：从剧本自动生成分镜和提示词。

任务：

```text
AI Model Gateway 初版
script_analysis task
shot_prompt_generation task
LLM provider 适配器
任务状态表
任务进度 API
WebSocket 或轮询
```

验收：

```text
提交剧本后创建异步任务
任务完成后生成 scenes 和 shots
每个 shot 有 image_prompt 和 video_prompt
失败任务能看到错误并可重试
```

### 阶段 4：图片生成和素材库，2-3 周

目标：单个分镜可以生成图片候选，并保存为素材。

任务：

```text
image_generation task
图片 provider 适配器
对象存储上传
缩略图生成
assets 表和素材库 UI
shot 关联图片素材
图片候选选择
```

验收：

```text
从 shot 节点发起生图
任务状态实时更新
图片完成后出现在素材库
图片节点出现在画布
可以选择某张图片作为镜头首帧
```

### 阶段 5：视频生成和时间线，2-3 周

目标：选中图片生成视频，并自动进入粗剪时间线。

任务：

```text
video_generation task
视频 provider 适配器
视频素材保存和预览
shot 关联视频素材
timeline 自动生成
基础时间线 UI
```

验收：

```text
选中图片后可以发起图生视频
视频生成完成后关联回 shot
按 shot_no 自动生成 video track
可以预览每个 clip
```

### 阶段 6：导出，1-2 周

目标：导出素材包和 MP4。

任务：

```text
material_package_export task
storyboard.csv
prompt_list.csv
timeline.json
subtitles.srt
FFmpeg MP4 合成
exports 表和导出中心 UI
```

验收：

```text
可以导出 zip 素材包
素材包包含视频、图片、分镜表、提示词表、timeline.json
可以导出 preview.mp4
导出任务失败可查看错误
```

## 3. 第一版演示脚本

```text
1. 打开首页，创建“万里寻子”项目。
2. 粘贴一段 500 字短剧剧本。
3. 点击 AI 拆分，等待生成分镜。
4. 切换到画布，看到分镜节点。
5. 选择 S001，点击生成图片。
6. 从图片候选中选择一张。
7. 点击生成视频，等待视频回写。
8. 打开时间线，看到 S001 视频 clip。
9. 点击自动组装全部可用镜头。
10. 导出素材包和 MP4。
```

## 4. 验收标准

### 4.1 功能验收

| 能力 | 标准 |
| --- | --- |
| 项目管理 | 项目 CRUD 完整，刷新不丢数据 |
| 分镜 | 支持手动编辑和 AI 生成 |
| 画布 | 节点、连线、位置持久化 |
| 任务 | 任务状态清晰，可失败、可重试 |
| 素材 | 图片和视频能预览、追溯来源 |
| 时间线 | 能按分镜顺序生成粗剪 |
| 导出 | 能产出 zip 和 MP4 |

### 4.2 技术验收

```text
API 有 OpenAPI 文档
数据库迁移可重复执行
本地 Docker Compose 一键启动依赖
前端无关键 TypeScript 错误
后端核心 service 有单元测试
Worker 任务有失败重试和错误记录
对象存储路径有项目隔离
```

## 5. 测试策略

| 层级 | 覆盖内容 |
| --- | --- |
| 后端单元测试 | service、provider adapter、导出数据结构 |
| API 测试 | projects、shots、canvas、tasks、assets |
| Worker 测试 | 任务状态、失败重试、素材写入 |
| 前端组件测试 | 分镜表、节点属性面板、任务状态组件 |
| 端到端测试 | 从创建项目到导出素材包 |

## 6. 主要风险

| 风险 | 处理方式 |
| --- | --- |
| AI 模型输出不稳定 | 输出 JSON schema 校验，失败自动修复或要求重试 |
| 视频生成耗时长 | 全部异步任务，前端不阻塞 |
| 画布状态复杂 | 画布节点只存 UI 状态，业务数据仍以 shot/asset 为准 |
| 文件体积大 | 使用对象存储，数据库只存 key |
| 剪映草稿兼容差 | 第一版只做素材包和 timeline.json |
| 成本不可控 | 每个任务记录 provider、model、usage |
